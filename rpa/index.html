CASE · RPA SELF-TEST

电商订单 RPA 自测项目

影刀 RPA · Python · SQLite · 2026.11

本地模拟三个平台的订单页，用影刀和 Python 各实现一套采集：联合键去重 → 逐字段对账 → 三类故障注入 → 失败表。不是客户交付项目，但流程、异常处理和六份文档按交付标准做。

本地桌面 RPA · 无公网演示 回到作品集

01测试对象与规模

模拟环境

  • 本地模拟三个平台的订单页
  • 20 条订单，待审核 9 条
  • 合计金额 2792.30 元
  • 影刀与 Python 两套实现，结果互相对照

验证结果

  • DAY1 / DAY2 / DAY3 全部 PASS
  • 三类故障注入均按预期处理
  • 失败表 22 条，可按批次 / 订单号 / 错误类型查询
  • 六份交付文档

02异常处理设计

  • 错误分三类，只有一类值得重试：元素超时可重试；数据错误和页面结构错误不重试，直接进失败表。
  • 同一字段在 ≥80% 行缺失 → 判定「疑似页面改版」，整批失败告警，而不是把 20 行空值写进库。
  • 失败记录保留原始行定位与错误原因，方便人工补录后重跑单批。

03演示边界

RPA 依赖影刀客户端和本地模拟网页，无法在浏览器里在线运行，所以这里提供的是作品说明而不是假演示。页面上的订单、金额和平台均为本地模拟数据，不连接任何真实店铺后台。

相关项目：服装辅料订单流水线、公开网页采集器（可在线试跑）。
