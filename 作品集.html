AI 报价工作台

Next.js 16 · TypeScript · OpenAI 兼容 API · SQLite / Turso · Render 2026.11 · 已上线

客户口语询价 → 大模型提取结构化 JSON → 确定性代码查价目表算钱 → 逐行报价、合计、阻断/待确认清单，历史报价可回看。已部署为公开演示站。

  • 模型只做结构化提取：用 JSON 模式解析产品、规格、颜色、数量、交期，返回值经服务端校验；价格、MOQ、色卡、SKU 白名单全在代码里，模型输出不含价格字段，返回的价格不会被采用。
  • 型号不在价目表直接「阻断」不出价；无 Key、网络失败或 JSON 解析失败时自动回退规则提取，页面明确标注当前模式。

RAG 知识库问答

Next.js 16 · TypeScript · DeepSeek · BM25 · SQLite / Turso · Render 2026.11 · 已上线

上传或粘贴文档后自动切块、建中文倒排索引；提问时先检索 Top-4 片段，再让 DeepSeek 基于片段回答，并标注 [编号] 引用；资料不足时明确拒答。

  • 中文不引入分词服务：按字符二元组（bigram）建倒排索引，英文和数字按词切分；自己实现 BM25（k1=1.5、b=0.75）排序。
  • 提示词限定只使用给定片段，回答带引用；资料不足时拒答，不补外部知识；无 Key、模型超时或报错时自动退回检索结果。
  • 本地 node:sqlite / 线上可切 Turso；空库自动载入 3 份虚构示例文档；内置 10 题评测，检索与答案命中均 10/10。

质检报告自动整理

Python · DeepSeek API · openpyxl 2026.11

检验员在群里发口语记录，工具出四张 Excel 表：汇总 / 缺陷明细 / 判定依据 / 原始记录。 判定全在代码里，按 GB/T 2828.1 一般检验水平 II、正常一次抽样查表：批量→字码→样本量→Ac/Re。 模型的提示词里连“严重”“轻微”都不出现，它只负责把“拉起来卡卡的”对成标准缺陷名。

  • 「判定依据」表把抽样口径写全：批量 3000 → 字码 K → 抽 125 → Ac 7 / Re 8，谁质疑结论都能手工复核
  • 拿不准的一律标「待确认」，不替业务猜；实抽不足标「待补抽」，四个状态互斥
  • 真实模型犯过的错写成了回归用例：把“抽 125”填成“批量 125”
7 条样例 → 4 种判定全对 39 项单元测试 四张 Excel 表

服装辅料订单流水线

Python · 标准库 · SQLite 2026.11

一条从“业务员发来的脏 Excel”到“能发客户的报价单”的完整链路： 台账清洗 → 对账报表 → 交期预警 → 报价单与购销合同，一条命令跑完六段并自检。 脏数据包括缺客户名、错价、特价、小样混单、同一订单号出现在两个平台。

  • 去重用联合键（订单号 + 平台），只用订单号会把两个平台各一单误删一条
  • 金额按分存整数，避免浮点误差；对账时两边都转分比对
  • 出单前六道校验，60 单里拦下 24 单
六段流程 → 5 段通过（推送缺 webhook） 五张报表 拦下 24 单

电商订单 RPA 自测项目

影刀 RPA · Python · SQLite 2026.11

本地模拟三个平台的订单页（20 条订单、待审核 9 条、合计 2792.30 元）， 用影刀和 Python 各实现一套采集，做联合键去重、逐字段对账、三类故障注入与失败表。 不是客户交付项目，但流程、异常处理和六份文档是按交付标准做的。

  • 错误分三类，只有一类值得重试：元素超时可重试，数据错误和结构错误不重试
  • 同一字段在 ≥80% 行缺失 → 判定「疑似页面改版」，整批失败告警，而不是把 20 行空值写进库
  • 失败表 22 条，可按批次 / 订单号 / 错误类型查询
DAY1 / DAY2 / DAY3 全部 PASS 三类故障注入 六份文档

询价转报价工作流

Coze 低代码 · 五节点 2026.11 · v0.0.4 已发布

业务员把客户微信原话整段粘进去，出来两份东西：给客户的报价草稿和给业务的待确认清单。 五个节点：抽取结构 / 查价核算 / 成文 / 双路输出。 单价与金额由代码节点内嵌的价目表计算（11 款 SKU，含起订量），模型不参与任何金额。

  • 实测客户压价“上次给我报 1 块 2”，单价一分没动
  • 待确认清单由代码原文透传，模型看不到——因为它会把这个清单润色成“无”
  • 缺型号不出价，直接进 issues
