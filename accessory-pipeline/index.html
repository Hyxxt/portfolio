CASE · LOCAL PIPELINE

服装辅料订单流水线

Python · 标准库 · SQLite / openpyxl · 2026.11

从“业务员发来的脏 Excel”到“能发客户的报价单”的完整链路：台账清洗 → 对账报表 → 交期预警 → 报价单与购销合同生成 → 六道出单校验 → 自检，一条命令跑完。

本地命令行项目 · 无公网演示 回到作品集

01为什么做这个

外贸和辅料订单的原始台账通常是多个业务员各自维护的 Excel：单位混用、色号写法不统一、重复单、空字段、数字存成文本、日期有四种写法。直接拿去对账或出报价单，错一个零就是真金白银的损失。

这条流水线把“能算的算、不能算的不猜”落到了每一步：客户名缺失标「待补」，不用地址或联系人反推；金额一律按数量 × 单价重算，不信任原始金额列。

02流程与结果

五段流水线

  • 台账清洗：单位、色号、日期归一，联合键去重
  • 对账报表：订单汇总 / 客户对账 / 交期预警 / 异常清单 / 口径说明
  • 交期预警：按承诺交期分级，输出待跟进名单
  • 报价单与合同：批量生成 Word / Excel 文档
  • 自检：金额、单号、客户、日期六道校验

实测数据

  • 造 65 行台账，埋 8 类脏数据 + 12 笔业务异常
  • 清洗后 60 行，8 类埋点全部抓到
  • 报表 5 个 sheet，问题按 P0/P1/P2 分级
  • 出单前六道校验：60 单 → 36 出单、24 单被拦
  • 16 项自检全过

03关键设计

  • 去重用 联合键（订单号 + 平台）：只用订单号会把两个平台各一单误删一条。
  • 金额按分存整数，对账时两边都转分比对，避免浮点误差。
  • 出单前拦截而不是“先出再改”：缺客户名、金额对不上、交期缺失的单直接拦下并写明原因。
  • 企微推送节点因缺少 webhook 未实际发送，其余五段均已跑通——边界写在报告里。

04演示边界

这是一个本地命令行工具，依赖业务方提供的 Excel 文件和本机环境，没有做成公网 Web 服务，因此不提供在线演示。项目使用的全部为程序生成的模拟数据，不含真实客户信息。

同一条“算钱交给代码”的思路也用在其他项目：询价转报价工作流、质检报告自动整理、搜索词体检。
